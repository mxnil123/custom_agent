Engineering Pre-Build Specification: Frugal, Programmatic Agent Harness with Zero-Cost Gemini Web BackendStatus: Pre-Implementation BlueprintTarget Runtime: Python 3.11+ Agent Harness + Go Web-to-API Proxy (zexadev/gemini-web2api-go)   1. GoalsWe are building a low-token, low-cost, high-control agent harness that executes multi-step tasks and external tool calls without burning context windows or paid API quotas:Zero-Cost Model Inference: Route eligible inference through gemini.google.com web sessions exposed as an OpenAI-compatible API, eliminating paid API keys/quotas for supported tiers/models.   Programmatic Tool Calling (PTC): Let the agent write sandboxed Python code that loops, filters, aggregates, and chains tool calls locally—returning only concise results to the LLM instead of dumping raw payloads into context.Strict Token Economy: Minimize input/output tokens across every stage via prompt cache hygiene, progressive tool discovery, sub-agent context isolation, observation masking/file spilling, compact tabular serialization, and model/tier routing.Clean Separation of Concerns: Keep each optimization in a dedicated, composable repository so engineers can debug, swap, or disable any layer independently.2. Methods & Engineering RulesA. Zero-Cost Web-to-API Backend (gemini-web2api-go)Expose gemini.google.com as an OpenAI-compatible endpoint (/v1/chat/completions, /v1/models) using zexadev/gemini-web2api-go (which includes Chrome TLS fingerprinting, cookie pool auto-renewal, proxy pool support, and SQLite/DB metrics).   Operational rules:Run with cookie/proxy rotation and explicit model mappings; treat web-session proxying as subject to upstream rate limits, session/cookie expiry, and simulated multi-turn history (so keep prompts compact and rely on harness-managed state).   Never log raw prompts/responses to persistent storage if sensitive data passes through.B. LLM Routing & Prompt Cache HygieneStatic Prefix Discipline: Keep system prompts, role instructions, and top-level tool declarations byte-for-byte identical across turns so prefix/KV caches stay warm. Put dynamic timestamps, run IDs, or changing state in the latest user/tool message—never in the system prompt.Append-Only History + Observation Masking: Never mutate earlier messages in place (which breaks prefix caches). After a tool output has been consumed and summarized, mask/compact bulky historical tool payloads via harness history processors while preserving reasoning and final decisions, and spill large raw outputs to a local workspace directory instead of printing megabytes to stdout.Model Tiering: Route complex planning/orchestration to a stronger model and noisy/routine sub-tasks to faster/cheaper models via the proxy/router layer.C. Progressive Tool Discovery + Programmatic CallingDeferred Tool Search: Do not dump dozens of MCP tool schemas into the system prompt upfront. Expose a discovery/search mechanism (search_tools) so the agent loads only the specific tool interfaces/bindings needed for the current task.Code-First Batching: For multi-call or data-heavy operations (e.g., querying APIs/DBs, filtering records, joining results), have the agent execute a script in the sandboxed code executor that performs filtering/aggregation inside code and returns only the distilled output.D. Sub-Agent Context IsolationDelegate high-noise exploration (reading many files, searching logs, broad lookups) to ephemeral sub-agents with isolated context windows.Sub-agents consume the noisy intermediate tokens locally and return a compact summary to the main orchestrator.E. Compact Tabular SerializationWhen returning uniform lists of records/objects from scripts or tools into model context, serialize them into compact tabular format (toon-format/toon) rather than verbose repeated JSON keys.3. place dynamic run metadata in user messages.Add a history processor that masks/truncates large old tool outputs after subsequent turns while keeping history append-only.Exit criteria: Multi-turn conversation works with bounded context growth and zero accidental mutation of the system prompt.Phase 3: Add Sub-Agent IsolationIntegrate vstorm-co/subagents-pydantic-ai to expose a sub-agent delegation tool (e.g., for codebase/log/web exploration) routed to agent-worker.Enforce a contract requiring sub-agents to return structured/concise summaries rather than raw dumps.Exit criteria: Orchestrator delegates a multi-file/noisy lookup to a sub-agent and receives a compact summary without polluting the main agent's context.Phase 4: Wire Progressive Tool Discovery, Code Mode & TOONAttach datalayer/agent-codemode to your pydantic-ai agent, register target MCP servers, and configure a workspace directory for spilling large intermediate files.Inside code-mode scripts/helpers, use toon-format/toon when formatting uniform record lists returned to the model, while writing massive raw datasets to workspace files.Exit criteria: Agent uses search_tools to discover a tool on demand, runs a multi-step Python script that filters/aggregates MCP data in one turn, and receives a compact TOON/summary output.Phase 5: End-to-End Stress & Guardrail CheckRun an end-to-end benchmark task (multi-step tool aggregation + noisy exploration + multi-turn follow-ups).Verify: (a) total tokens per task vs. naive JSON tool calling, (b) graceful handling of gemini-web2api-go errors/throttling, (c) sandbox boundaries on executed Python code, and (d) no sensitive prompt/response leakage in logs.Key Risks & Mitigations Before CodingUpstream Web Proxy Fragility: Web endpoints can throttle, change behavior, or invalidate cookies. Wrap calls with retries/timeouts in LiteLLM and keep a fallback model route ready if needed.
